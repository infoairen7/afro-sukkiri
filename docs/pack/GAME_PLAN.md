# アフロ、スッキリ。 ゲーム企画・制作仕様書

バージョン 1.1 / 2026-10-06 / 仮タイトル・数値はプレイ検証前の初期案

## 1. コンセプト

**刈って、つるっと、気分爽快。**

丸いアフロのおじさんの髪をバリカンで剃るだけの、スマートフォン・PC対応3Dブラウザゲーム。指を動かした跡だけ髪が短くなり、毛束がポロポロ落ち、最後は全周ツルツルになる。上手に全剃りできたらクリアタイムとスコアをXに投稿できる。

おじさんは散髪を楽しみにしている、架空の陽気なキャラクター。驚き、くすぐったい表情、最後の満面の笑みを見せる。血・傷・痛がる反応は入れず、音と見た目の変化を楽しむ。眉毛と口ひげはキャラクターの特徴として残す。広告、課金、育成、物語、オンラインランキングは初版に含めない。

### 体験の柱

1. 入力にすぐ反応する：刃が当たった部分だけ、0.1秒程度で変化が分かることを目標にする。
2. 刈り心地が変わる：髪型とバリカンで、刈れる幅・速さ・音・毛の散り方を変える。
3. 最後まで気持ちいい：刈り残し表示、ワンタップ視点切替、最後の3％の補助を用意する。
4. 共有したくなる：ビフォー／アフター、タイム、スコア、ランクを一枚にまとめる。

想定1プレイは30～90秒。制限時間で失敗する仕様にはせず、タイムはクリアまで加算する。誰でも最後まで剃れる。時間の数字が気になる人はフリーでHUDタイムを隠せる。

## 2. 同梱物と完成度

| 種別 | 内容 | 用途・状態 |
|---|---|---|
| デザイン画 | キャラ・髪型、バリカン、スマホ3画面のPNG各1枚 | 完成イメージ。画面中の細かい色・順序より本仕様を優先 |
| 3Dおじさん | 基本1名＋喜怒哀楽4名、計5点 | 球体等から作った簡易バストモデル。リグ／表情モーフなし |
| 髪型 | GLB 8点＋毛根JSON 8点 | 静的な形状見本。各毛束の位置・長さが取得可能 |
| バリカン | GLB 6点 | 簡易小物。機能の挙動はClaudeが実装する |
| 実装資料 | 本書、Claude依頼文、カタログJSON、UIトークン、スコア／X共有の補助コード | 完成ゲームではなく制作開始用パック |

**PNGの精密な顔・毛髪・質感が、そのままGLBになっているわけではない。** 同梱GLBで操作を完成させた後、デザイン画を参照して顔、巻き毛、ケープ、表情を磨き込む。2D画像を平面に貼っただけの表現で3D操作を代替しない。

## 3. ゲームの流れ・モード

タイトル → おじさん・髪型・道具を選ぶ → はじめる → 最初に髪へ触れる → 刈る → 全周を仕上げる → 結果 → X投稿／画像保存／もう一度。

| モード | ルール | 記録 |
|---|---|---|
| スッキリフリー（初期選択） | 道具6種を自由に切り替える。時間制限なし。停止・再開可 | タイム・スコアに「フリー」と明記。道具構成を保存 |
| タイムアタック | 髪型を選び、スタンダード1本固定。道具変更不可 | 同じ髪型・seed・ルール版の自己記録と比較 |

すべての髪型・道具は最初から選べる。初回だけ「なぞって刈る」「向きを変えて、後ろも」の短いガイドを出す。選択画面は2列カード、タップで3Dプレビュー、選択状態は枠＋チェック＋名称で示す。

### 状態と計測

- loading：アセットの進捗と再試行を表示。WebGLを利用できない場合は環境案内を出す。
- ready：髪型を確認できる。タイムは0。開始後の最初の有効接触でrunningに移る。
- running：performance.now()等の単調時計で計測。回転中、道具選択中も加算。表示更新回数で計測しない。
- paused：フリーでは経過時間を保持し、非操作時間は除外。タブ非表示で音・入力を止める。
- タイムアタックで停止またはタブ非表示：記録対象外にして練習として継続可能。「中断あり」と明記し、通常記録と混ぜない。
- complete：全毛根の残量がゼロになったシミュレーション時刻で確定。祝福演出の長さを加算しない。結果値を固定する。
- restart：髪、乱数、タイマー、使用道具、効果、入力をすべて初期化。途中リセットのみ確認する。

## 4. スマホ操作・レスポンシブ

### 操作

| 操作 | スマホ | PC |
|---|---|---|
| 剃る | 頭の上を1本指でなぞる／置いたまま | 左ドラッグ／押したまま |
| 向きを変える | 正面・右・後ろ・左・上のボタン | 同じボタン、補助で数字1～5 |
| 自由回転（補助） | 「回す」切替ONの間だけドラッグ | 同じ切替。剃る操作と同時に動かさない |
| 道具を選ぶ | 下部の道具ボタン | 同じボタン |

一度に受け付ける剃り入力は1本。2本目の接触で刈り面積を増やさない。視点変更は指を離してから反映し、切替前後の座標を一本のストロークとしてつなげない。刀身の中心と判定位置を一致させる。指の少し上に刃先を表示する設定は標準32 CSS px、0～48pxで調整可能。輪郭円で正確な判定位置を見せる。PCのオフセットは0。左利きではグリップの傾きを反転。

カメラは、おじさん正面が+Z、上が+Y。正面15°、左右5°、後ろ0°、上70°程度の俯角を初期値とし、全毛根に到達できるか検証する。「右／左」はおじさん本人の向きで統一。自由回転は俯角-20～75°、拡大は安全範囲に限定。回転中は剃れない。

### 画面レイアウト（390×844 CSS pxの基準）

| 領域 | 目安 | 内容 |
|---|---|---|
| セーフエリア＋上部 | 上端から約104px | 一時停止、モード、タイム、スッキリ率 |
| 3Dステージ | 約104～606px | 大きな頭、刃先、刈り跡、少量の毛片 |
| 視点ボタン | 約606～658px | 正面／右／後ろ／左／上、残りがある面に小さな印 |
| 道具トレイ | 約666～738px | 6アイコン、選択名・機能を表示 |
| 下部 | 残り＋safe area | 短い操作ヒント、音・演出設定 |

これは固定ピクセル指定ではなく余白配分の目安。360px幅・高さ640pxでも主要操作を常時表示。縦方向は100dvh、下部safe-area-inset-bottomを吸収。プレイ領域のみtouch-action:none、メニューは通常スクロールと拡大を許容する。スクリーン全体でピンチズームを禁止しない。各タップ領域は44px以上を目標にする。320px幅では道具を3列2段に再配置。横画面は3Dを左、操作を右へ。PCはステージ幅最大960px、右に髪型・道具パネル。

HUDは数字の桁幅を固定する。canvas内だけにUIを描かず、ボタン・設定・結果はHTMLで作り、名前、フォーカス、選択状態を付ける。コントラストは濃紺文字で確保。音なしでも刈り進捗が分かるようにする。

## 5. キャラクター・髪型

丸顔、太めの眉、小さい口ひげ、大きめの耳、水色の散髪ケープ。40～50代くらいの親しみやすい架空のおじさん。基本1名に喜怒哀楽4名を追加し、計5名。顔立ちと選択仕様はCHARACTERS_V1_1.mdを参照。実在の人物に似せない。頭身は写実よりデフォルメ。背景は明るい小さな理髪店をぼかし、頭の輪郭を見やすくする。

表情目標：待機の微笑み、刈られた時のくすぐったい目、広く刈れた時の小さな驚き、完成時の笑顔。1回の反応は短くし、頻発させない。頭が判定に影響するほど揺れない。完成直前に勝手に動いて剃り残す仕様は避ける。

|---|---|---|---:|
| classic | まんまるアフロ | 黒い丸アフロ。標準の気持ちよさ | 45 |
| jumbo | メガ盛りアフロ | 茶色でひと回り大きい。大きな毛束が落ちる | 65 |
| tight | くるくるパーマ | 小さく密なカール。短時間向け | 35 |
| mohawk | 炎のモヒカン | 中央はオレンジで高く、側面は短い黒髪 | 40 |
| twins | ツインもふもふ | 青い左右の毛玉。中央と後ろにも短い毛がある | 45 |
| swirl | うずまきヘア | 茶色の流れ。仕上げで長短が残りやすい | 50 |
| flat | 角刈りタワー | 上面が平たい黒髪。面を削る爽快感 | 45 |
| rainbow | 虹色アフロ | パステルの虹色。形・難度はclassicと同じ | 45 |

Pはテスト前のバランス案。数値を変更したらルール版も更新する。毛色は外見だけに影響。髪型の量、長さ、毛根配置は固定seedで再現する。各髪型は頭の別領域に毛が生えるのではなく、同じ基本頭皮マスクを使って長さと形を変えている。

## 6. バリカン6種類

刃幅は頭のローカル座標に対するブラシ半径r、刈り速度vは髪の高さを減らすゲーム単位／秒。表の値は実機調整前。実物の製品性能を表す数値ではない。

| ID | 名称・色 | r / v | 固有機能 | 使い分け |
|---|---|---|---|---|
| standard | スタンダード・水色 | 0.16 / 1.00 | 均一に刈れる基本機 | これ1本で必ず完了できる |
| wide | ワイド・黄 | 0.25 / 0.80 | 横に広い刃。広範囲を削る | 細部は小さい道具が快適 |
| turbo | ターボ・コーラル | 0.16 / 1.55 | 連続運転中3秒ごとに1秒だけ2.0へ加速 | 加速を光と音で示す。停止時周期リセット |
| vacuum | 吸引バリカン・ミント | 0.16 / 0.95 | 刈れた毛が透明窓へ吸い込まれる | 視界がすっきり。未接触の毛は吸って剃らない |
| detail | キワ剃り・濃紺 | 0.09 / 1.00 | 毛根の残りを円で強調、細い刃 | 耳周りや小さい刈り残しに使う |
| polish | つるピカ・ラベンダー | 0.18 / 0.45 | 高さ0.08以下では速度2.0、磨き跡の一瞬の光 | 長髪もゆっくり刈れる。仕上げ特化 |

すべてのバリカンは最終的に0まで剃れる。充電、故障、課金ロック、強制的な持ち替えは入れない。機能はボタンを増やさず、選ぶだけで働く。吸引・ターボ・磨きは単なる色違いにならないよう、音と視覚も変える。キワ剃りの強調表示は全道具にある残毛ガイドより細かい円を追加する。

## 7. 剃る処理とクリア条件

### 実装方針

Three.jsの3Dモデル＋HTML UIを想定。最初は同梱の毛根データを正とし、髪をInstancedMeshにまとめて描画する。GLB髪型は形状確認用で、数百個の独立Meshのまま毎フレーム描画するのは避ける。髪はスカルプと別のオブジェクトにする。[S3]

毛根ごとにposition、normal、growthDirection、initialHeight、currentHeight、radius、color、weightを持つ。normalは頭皮法線、growthDirectionは描画する毛の成長方向。通常は同じだが、flatの上部は+Yに伸ばす。原点は頭中心、頭の楕円体半径は[0.78, 1.00, 0.78]。眉、ひげ、耳、顔は刈る対象に含めない。

1. ポインターをcanvas矩形からNDCへ変換し、Raycasterで髪または頭皮を取得。髪はinstanceIdから毛根を特定する。[S4]
2. アフロが頭皮の投影範囲からはみ出す場所も刈れるように、髪のヒットを先に扱う。頭皮にレイが当たる場合はその座標を使える。
3. ヒットを頭ローカルへ変換する。ブラシ半径内の毛根を、正面側の法線判定と頭による遮蔽判定を通して選択する。反対側まで貫通させない。
4. 短いシミュレーション刻みで currentHeight=max(0, currentHeight - v*dt) を更新。ポインター移動を補間し、速いスワイプでも抜けを防ぐ。
5. ストロークの補間点ごとにdt全量を重複適用しない。dtは移動区間に分配し、同一時間スライスの毛根処理を重複計上しない。フレーム／イベント頻度で有利にならないようにする。
6. 毛束中心=root+growthDirection*height/2、縦スケール=height/2。毛束幅も残量に応じて縮め、根だけ太い球が残らないようにする。高さ0.002以下は0へ丸めて非表示。ゼロスケール行列のraycastは避け、活動インスタンスを詰めてinstanceId対応表を更新するか、別の当たり判定を使う。
7. 質感向上段階では毛束を数本のカールや短い毛に置き換える。剃った場所に黒いベースキャップを残さない。

**スッキリ率C** = 高さが0になった毛根の重み合計 / 全対象毛根の重み合計。同梱データは全毛根weight=1。毛の体積が減った割合は演出補助に使えても、完了判定を代替しない。

**クリアは全対象毛根が0のときのみ。** 99％を100％と表示しない。未完了の表示は小数1桁で切り捨て、完了時のみ100％へ。長い毛が一本でも残っているのに「綺麗に全剃り」と判定しない。

残り3％以下では毛根位置を控えめなリングで示し、該当視点ボタンに印を付ける。仕上げ補助ON時はブラシ半径を1.35倍にするが、自動で残毛を消さない。補助設定は記録に保持し、タイムアタックでは全員ON固定。低品質設定でも判定毛根数は減らさず、表示だけ簡略化する。

## 8. スコアと記録

```text
C = 全対象毛根のうち高さ0になった重みの割合（0～1）
T = 記録上の経過秒（最初の有効接触～全剃り）
P = 髪型ごとの基準秒
E = 髪が実際に減った時間 / 刈り操作を押し続けた時間（0～1）
score = round(60000*C + 30000*min(1, P/max(T,0.01)) + 10000*E)
```

上限100,000。止まって眺めた時間はTに含めるが、Eの分母には含めない。頭の外や剃り済み部分で押し続けるとEの分母だけ増える。1シミュレーション刻み内で毛が少しでも減ればその刻みをproductiveとし、毛根数や補間点数を掛けて加算しない。未開始／分母0はE=0。

得点は完了時だけ正式表示する。途中離脱時に高い速度点を使ってクリア記録を生成しない。ランクはSS:98,000以上、S:92,000以上、A:84,000以上、B:70,000以上、C:それ未満。称号は罵倒せず「スッキリ達成」等にする。

例：classic、T=28.46秒、C=1、E=0.92なら60,000+30,000+9,200=99,200点、SS。基準秒内の速さは速度点満額になるため、それ以上の競争は別表示のクリアタイムで行う。自己ベストは最短タイムと最高点を別保存する。

記録データ：version、mode、characterId、hairId、seed、toolIds、assist、elapsedMs、score、rank、completed、interrupted、createdAt。localStorageにルール版・モード・髪型別で保存。端末保存なので別端末と同期しない。個人の投稿用記録であり、サーバー検証された競技記録ではない。オンラインランキングは別途要件化する。

## 9. X投稿・結果画像

### 結果画面

「つるっと完了！」、笑顔の3Dおじさん、タイム（00:28.46）、99,200点、SS、スッキリ100％、人物名、髪型、モード、使用道具、ビフォー／アフター。「Xで記録をポスト」「結果画像を保存」「もう一度」の順で配置する。

### 文章共有

X Web Intentの https://x.com/intent/tweet にtext・url・hashtagsを渡し、本人が確認して投稿する画面を開く。ゲーム側でX認証情報を持たず、勝手に投稿しない。リンクをタップイベントに直結させ、iframe内に投稿画面を埋めない。[S1][S2]

```text
アフロ、スッキリ。で全剃り達成！
28.46秒 / 99,200点 / SS
にこ丸・まんまるアフロ・フリー
#アフロスッキリ #ブラウザゲーム
（公開したゲームのURL）
```

公開URLは設定から読む。未公開・localhostではurlを省略し、架空URLを付けない。encodeURIComponent相当のURLSearchParamsで日本語と記号をエンコードする。Xアプリなし／未ログインのケースも確認する。戻っても結果を失わない。共有操作の完了を投稿成功と断定しない。

### 画像共有

1200×630pxの結果カード：左にビフォー、右にアフター、中央下にタイム・得点・髪型・モード、上にタイトル。数字を最優先に、余白48px、目安40～64px文字。標準OG画像とは別にプレイ結果からCanvasで作る。

Web Intentの文章・URLリンクだけでローカルPNGが自動添付される設計にしない。基本は「結果画像を保存」後、Xの投稿画面で本人が添付。追加でnavigator.canShare({files})が通る端末だけ「画像を共有」を表示してOS共有シートを開けるが、Xの表示や選択は保証しない。HTTPS、ユーザー操作、非対応時の保存フォールバックが必要。[S5]

3Dキャプチャは描画直後に取得するか専用レンダーターゲットを使う。常時preserveDrawingBufferに依存しない。同一オリジンの画像・フォントでCanvas汚染を防ぐ。生成失敗時は文面コピーとリトライを提示。共有キャンセルはエラー扱いしない。

## 10. デザイン・音・演出

| トークン | 色・値 | 用途 |
|---|---|---|
| ink | #123B4A | 見出し・本文・Xボタン背景 |
| aqua | #65D6E8 | 主役の水色・主操作 |
| cream | #FFF8ED | 背景・カード |
| coral | #FF855E | スコア強調・ターボ |
| yellow | #FFD15C | 星・ランク・ワイド |
| mint | #93D8C6 | 吸引 |
| lavender | #B6A0E8 | つるピカ |
| radius | 16 / 24 / 999px | カード／大カード／ピル |

日本語は丸みのある読みやすいゴシック。数値はtabular-nums。配色だけで機能を区別せず、道具名と刃形状を併用。大量の毛片で頭が見えなくならないよう、粒子は1秒程度で消す。背景より顔、顔より髪の変化、最後にスコアへ視線を誘導する。

音：電源の小さなクリック、モーターの低いループ、毛量に反応する短いザリザリ音、毛束落下の軽い音、完成の短いチャイム。大きな叫び声や突然の爆音は使わない。BGM初期OFF、効果音ON（最初のタップ後に再生を開始）、個別音量・ミュート。音素材自体は未同梱。ClaudeはWeb Audioの合成音で仮実装し、必要なら後で差し替える。

振動は対応端末のみ任意設定。未対応でも通常プレイ可。画面揺れ・紙吹雪は控えめ、低刺激設定ではOFF。完了後の頭のハイライトは装飾で、追加の磨き作業をクリア条件にしない。

## 11. 技術目標と制作順

Vite + TypeScript + Three.jsを初期構成案とする。ライブラリ版は実装時に公式情報を確認して固定し、lockfileを含める。静的ホスティングで動く構成、サブディレクトリ公開に対応する相対パス、HTTPS。PWA・サーバー・アカウントは初版に必須ではない。

性能は**未計測の目標**：中程度のスマホで30fps以上、余裕のある端末で60fps。初回転送5MB程度を目標に、必要な髪型だけ読み込み、毛束はインスタンス化。DPR上限1.5～2、影は簡易、粒子は低品質40／標準120程度、重い物理エンジンは使わない。現在のGLBは形状確認のため数百ノードを含み、実行時の最適化は未実装。

| 段階 | 実装するもの | 完了の確認 |
|---|---|---|
| A・操作試作 | おじさん、classic、standard、視点切替、連続的に刈れる処理 | スマホとPCで後頭部まで剃れる |
| B・ゲーム成立 | タイム、完了判定、計算式、自己ベスト、再挑戦 | 残り1束でも完了しない。再挑戦で初期化 |
| C・共有 | 結果画面、X文面リンク、PNG保存 | 実際のタイムと点数が入り、公開URLが正しい |
| D・バリエーション | 全8髪型、全6道具、フリー／TA、音と粒子 | 固有機能が働き、全道具で完了できる |
| E・仕上げ | デザイン画に寄せたモデル磨き込み、モバイル最適化 | 実機の画面・操作・性能を確認 |

### 受け入れチェック

- iPhone Safari、Android Chrome、PC Chrome/Edge/Safariで実機確認。現行安定版を基準に、機種・OS・ブラウザ版を記録する。
- 360×640、390×844、430×932、横画面、タブレット、PCで主要UIが隠れない。
- 指がcanvas外へ出る、pointercancel、タブ切替、リサイズ時にバリカンが動き続けない。[S6]
- 正面を剃っても後頭部は減らず、すべての毛根へ到達できる。耳・顔・眉・ひげは消えない。
- 高速スワイプと押したままの両方で髪が減る。30/60fpsで同じ入力時間なら結果が大きく変わらない。
- 99％と100％の表示が正しい。完了演出でタイムが延長されない。中断記録が通常TA自己ベストに入らない。
- 例の計算が99,200点になる。NaN・負の秒・100,000点超えを保存しない。
- X文面と結果カードのタイム・得点が一致。投稿して戻っても結果を維持。画像を自動添付したと誤表示しない。
- 20回再挑戦してMesh・音源・イベント・粒子が累積しない。disposeとイベント解除を行う。
- ロード失敗、WebGL非対応、音再生不可、PNG保存不可、保存領域不可をそれぞれ案内して回復可能にする。
