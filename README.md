# アフロ、スッキリ。

**刈って、つるっと、気分爽快。** ― 丸いアフロのおじさんの髪をバリカンで全部剃る、スマホ縦画面優先・PC対応の3Dブラウザゲームです。
指でなぞった所だけ髪が短くなり、毛束がポロポロ落ち、全周ツルツルになったらタイムとスコアを確定して、X（旧Twitter）の投稿画面に結果を送れます。

- Three.js r185（WebGL）＋ TypeScript。ゲームロジックはDOM非依存の純粋モジュールで、Node標準のテストランナーで検証済み。
- 制作パック v1.1 の企画書・素材（GLB 19点、毛根JSON 8種、カタログ、スコア関数）をそのまま使用。
- ログイン・広告・課金・オンラインランキング・育成はありません。

---

## 1. すぐに遊ぶ・公開する（ビルド済み `dist/`）

同梱の `dist/` はそのまま静的ホスティングに置ける完成ビルドです（npm 不要）。

```bash
# ローカルで確認（どちらか）
npx serve dist            # Node がある場合
python3 -m http.server -d dist 5173   # Python がある場合
# → http://localhost:5173/ を開く
```

`file://` で直接開くと、ブラウザの制限でJSON/GLBを読めません。必ずHTTPサーバー経由で開いてください。

## 2. 開発環境で起動する

必要なもの：Node.js **22.18 以上**（推奨：24 LTS）。

```bash
npm install        # 初回のみ。package-lock.json が生成されます（→ コミットしてください）
npm run dev        # Vite 開発サーバー（同じLANのスマホからも http://<PCのIP>:5173/ で確認可）
npm test           # ゲームロジックの自動テスト（Node 標準テストランナー、39件）
npm run typecheck  # TypeScript 型チェック
```

## 3. ビルド

```bash
npm run build      # 型チェック → vite build → dist/
npm run preview    # ビルド結果をローカル確認
```

`vite.config.ts` は `base: './'` なので、`dist/` をサブディレクトリ（例：`https://user.github.io/afro-sukkiri/`）に置いてもそのまま動きます。

## 4. 公開方法

`dist/` の中身を HTTPS の静的ホスティングに置くだけです。サーバー処理・データベース・APIキーは不要です。

| 公開先 | 手順の要点 |
|---|---|
| GitHub Pages | `dist/` の中身を `gh-pages` ブランチ（または Pages の公開フォルダ）へ。サブディレクトリ公開OK |
| Netlify / Cloudflare Pages | ビルドコマンド `npm run build`、公開ディレクトリ `dist` |
| 任意のWebサーバー | `dist/` 一式をアップロード。`.glb` は `model/gltf-binary`、`.woff` は `font/woff` で配信されればOK（未設定でも大抵動きます） |

### 公開後に必ず設定すること

1. **公開URL**：`dist/config.json`（開発時は `public/config.json`）の `publicUrl` に、実際に公開した **https のURL** を書きます。
   ```json
   { "publicUrl": "https://user.github.io/afro-sukkiri/" }
   ```
   - X投稿画面に渡す `url` はこの値だけを使います。空・`http://`・`localhost` の場合は **URLを付けません**（架空URLは付けない仕様）。
   - ビルドし直さずに、公開後の `config.json` だけ書き換えても反映されます。
2. **OGP画像（任意）**：`index.html` の `og:image` を公開URLの絶対パス（例：`https://user.github.io/afro-sukkiri/og-image.png`）に書き換えると、URLを貼ったときにカード画像が出ます。

## 6. 仕様の実装メモ（企画書との対応）

### 髪と剃る処理（企画書 第7章）

- **髪は毛根JSONから再構成**：各毛根を「カール塊の連なり」として1つの `InstancedMesh` に描画（標準で約4,000インスタンス）。`currentHeight` は毛根ごとに保持し、刃が当たった毛根だけが短くなります。先端の塊から縮んで消えるので、毛根ごとに長さが変わる様子が見えます。髪型GLBは形状の参照として同梱のまま（実行時は読み込みません）。
- **当たり判定**：`THREE.Raycaster` で作ったレイを頭のローカル座標に変換し、
  ①各毛束（現在の高さのカプセル）②頭皮の楕円体 [0.78, 1, 0.78] ③顔パーツ（耳など）の楕円体 との最近接交点を解析的に求めます。髪のヒットを先に扱うので、頭皮の輪郭より外に膨らんだアフロも刈れます。ゼロスケール行列のraycastは使いません（企画書 7-6 の「別の当たり判定」）。
- **ブラシ**：ヒットした毛束の毛根（頭皮ヒットならその点）を中心に、刃幅 r 以内の毛根を刈ります。頭皮法線がカメラから大きく背を向けた毛根（内積 < −0.2）は除外し、**反対側を貫通して剃りません**。
- **高速スワイプ**：入力はタイムスタンプ付きで記録し、120Hz の固定刻みでポインタの軌跡を補間・再サンプリング（間隔 ≤ 刃幅の半分）。刻みの dt はサンプル点に**分配**するので、同じ時間スライスで1本の毛根が dt 以上削られることはなく、フレームレートやイベント頻度で有利になりません（30/60/144fps で結果一致をテスト済み）。
- **0.002以下は0に丸めて非表示**。スッキリ率は「高さ0になった毛根の重み／全重み」。未完了は小数1桁切り捨て（99.9%止まり）、**全毛根0のときだけ100%・クリア**。
- **耳に埋まる毛根**：データ上、約5%の毛根が耳の楕円体の内側にあり、短くなると見えなくなってしまいます。データは変更せず、**描画・当たり判定の根元だけ**を耳の表面まで成長方向にずらしています（`src/sim/parts.ts`）。
- **デザイン寄せの成長方向**：丸いアフロ系の髪型は、正面側の毛束が顔に向かって伸びると眉・目が隠れるため、描画と当たり判定に使う方向だけを上・後ろへ少し反らせています（`src/sim/style.ts`）。毛根位置・本数・高さ・重みなど得点に関わるデータはそのままです。角刈りの上向き成長（flat）はデータ通り。

### バリカン6種（第6章）

| 道具 | r / v | 実装した固有機能 |
|---|---|---|
| スタンダード | 0.16 / 1.00 | 基本機 |
| ワイド | 0.25 / 0.80 | 広い刃（輪郭円も大きい） |
| ターボ | 0.16 / 1.55 | 押し続けて3秒ごとに1秒 2.0 に加速（2〜3秒目）。離すと周期リセット。光（インジケータ発光）・音程・「ブースト！」表示 |
| 吸引 | 0.16 / 0.95 | 刈れた毛が落ちずに透明窓へ吸い込まれ、窓が少しずつ溜まる。刈る範囲は刃の範囲だけ |
| キワ剃り | 0.09 / 1.00 | 細い刃＋短い残り毛（高さ0.16未満）を細い水色の円で強調 |
| つるピカ | 0.18 / 0.45 | 高さ0.08以下は 2.0 に加速、磨いた所が一瞬キラッと光る |

すべての道具は高さに関係なく正の速度で刈れるため、どれでも最後まで剃れます（全道具で完走する自動テストあり）。仕上げ補助ONなら残り3%以下で刃幅×1.35（自動で消すことはしません）。

### スコア・記録（第8章）

- `snippets/share-score.mjs` を TypeScript に忠実移植（`src/core/score.ts`）。テストで原本と同一出力を確認。例（classic, 28.46秒, E=0.92）→ **99,200点 / SS**。
- `E = 髪が実際に減った刻みの時間 / 押し続けた時間`。頭の外・剃り済みの場所で押している時間は分母だけ増えます。
- 計時は `performance.now()`（単調時計）。最初に頭へ触れた刻みで開始、最後の毛根が0になった刻みで確定。祝福演出の時間は加算しません。一時停止中は除外。
- 記録は localStorage にルール版（1.1）・モード・髪型・seed 別に「最短タイム」と「最高点」を別保存。NaN・負の時間・100,000点超・未完了は保存しません。`characterId` の無い旧記録は `base` として読みます。保存できない環境では一時保存で続行し、その旨を表示。

### X共有・結果画像（第9章）

- 「Xで記録をポスト」は `https://x.com/intent/tweet?text=…&hashtags=アフロスッキリ,ブラウザゲーム&lang=ja[&url=…]` を `target="_blank" rel="noopener noreferrer"` のリンクで開くだけです。APIキー・認証情報は持たず、自動投稿もしません。投稿の確定は本人が行います。
- 文面例：
  ```
  アフロ、スッキリ。で全剃り達成！
  28.46秒 / 99,200点 / SS
  にこ丸・まんまるアフロ・フリー
  ```
- 「結果画像を保存」は 1200×630 のPNG。保存（ダウンロード）を試みると同時に画像をシートに表示し、ダウンロードが無視される環境でも長押し／右クリックで保存できるようにしています（左ビフォー／右アフター／中央にタイム・得点・ランク）。ビフォー／アフターは専用カメラで描画直後にコピーするため `preserveDrawingBuffer` に依存しません。フォントは同梱（同一オリジン）なのでCanvasは汚染されません。
- Web Intent に画像は自動添付されません（画面にも明記）。`navigator.canShare({files})` が通る端末だけ「画像を共有」ボタンを追加表示。共有キャンセルはエラー扱いしません。画像生成に失敗したら「文面をコピー」「もう一度作る」を表示。
- Xを開いて戻っても結果画面はそのまま。さらに直近の結果はタブ内（sessionStorage）に保持し、タイトルの「前回の結果」から再表示できます。

### 人物5名（CHARACTERS_V1_1）

- `data/characters.json` を正本に、いつものおじさん・にこ丸・むす鉄・しょん吉・ゲラ蔵をタイトルの「おじさん」から選択（2列の顔カード：その場でレンダリングした顔画像・名前・喜怒哀楽の文字・選択枠）。人物GLBと髪は同じ親Groupに原点・回転・倍率そのままで重ねています。
- 能力・得点差なし。結果カードとX文面に名前が入ります。
- 表情モーフは未同梱のため、名前付きの顔パーツ（眉・目・口・頬・涙）を動かす簡易リグで、待機（まばたき）／くすぐったい目／驚き／完成時の笑顔（にこ丸のうなずき、むす鉄の眉がゆるむ、しょん吉の涙が消えて口角が上がる、ゲラ蔵の大笑い）を付けています。頭は動かさず判定に影響しません（うなずきはクリア確定後のみ）。

### 見た目・音（第10章）

- 毛束：凹凸のある球をインスタンス化し、シェーダでコイル状の溝（バンプ＋陰影）を付けてカールに見せています。内側の塊ほど暗くして奥行きを表現。
- 剃った跡：頭皮の頂点色で「毛の下の影」を表現し、0になった所は素肌＋クリアコートのツヤに戻ります。
- おじさん：GLBの球を高解像度化し、肌は柔らかいビニール調、頭皮はツヤあり。ケープはひだ付きの手続き生成モデルに置き換え。背景は明るい理髪店をCSSでぼかし描画。
- 音（すべてWeb Audio合成）：電源クリック、道具ごとに音色の違うモーターループ、刈った量に応じたザリザリ音、毛の落下音、ターボ加速音、つるピカのキラッ音、完成チャイム、BGM（初期OFF）。効果音は最初のタップ後に開始。音量・ミュート・BGMは設定から。
- 粒子は約1秒で消え、同時数は標準120／軽量40。低刺激モードで紙吹雪・きらめき・背景アニメをOFF（OSの「視差効果を減らす」設定時は初期ON）。
- 画質「自動」：最初の数秒の描画が重い端末では表示だけ「軽量」へ1回切替（判定の毛根数は同じ）。

## 10. 残る制約・既知の課題

- **package-lock.json が未同梱**：制作環境から npm レジストリへの接続がネットワーク許可リストで拒否されたため、Vite の実行とロックファイル生成ができませんでした。`package.json` は全依存を**固定バージョン**（three 0.185.1 / vite 8.3.3 / typescript 6.0.3 / @types/three 0.185.0）で記載しています。初回 `npm install` で生成される `package-lock.json` をコミットしてください。
  - 同梱の `dist/` は、同じソースを esbuild 0.28.2（`scripts/build-local.mjs`）でバンドルしたものです。three.js は GitHub の r185 リリースタグ（npm の 0.185.1 と同一）から取得。Vite ビルドとは出力ファイル名が異なるだけで、コードは同じです。
- 同梱GLBは簡易形状のため、デザイン画の質感・造形には及びません（顔はGLBのパーツ構成を活かした改良まで）。表情はモーフではなくパーツの移動・拡縮による簡易表現です。
- 毛束は「塊の連なり」による近似で、1本1本の毛の物理はありません。
- 記録は端末内のみ（同期・サーバー検証なし）。オンラインランキングは対象外。
- 基準秒・刃幅・速度は企画書の初期案のまま（プレイテスト前）。変更時は `src/config.ts` の `RULE_VERSION` を上げてください。
- `?debug` を付けたURLでのみ有効なテスト用フックがあります（通常プレイでは無効）。
- Claude 上で公開したプレビュー版（アーティファクト）は、ページ側からのダウンロードと Web Share がブロックされる環境のため、「結果画像を保存」は画像の表示（長押し／右クリック保存）になります。通常のWeb公開では保存できます。
